## 2. タイトルの型

ほぼ全てが **「なぜ『身近な俗っぽい現象』は〜なのか【学問名（×学問名）】」**。

直近の伸びた回：
- なぜ「ミステリアスな人」に惹かれるのか【欲望の科学×日本美学】 52万
- なぜ「目上の者」は奢らなければならないのか【文化人類学】 27万
- なぜ「愛されること」が苦痛になる人がいるのか【愛着理論×比較生理学】 21万
- なぜ結婚相手は「一人」でなければならないのか【進化人類学】 20万
- なぜ世界中の怪物は「同じ見た目」なのか【認知科学×比較神話学】 20万

伸びにくい回：統計シミュレーション系、数理系（「名字は必ず絶滅する」5万など）。**恋愛・性・人間関係・社会のモヤモヤ**が強い。

ポイント：
- 「下世話な問い × 高尚な答え」。問いは誰でも感じている違和感、答えは学術。
- 【】内で学問を2つ掛け合わせると“ここでしか見られない”感が出る。
- **タイトルをA/Bテストしている**。同じ動画が取得のたびに別タイトルで表示された
  （例：「ミステリアスな人に惹かれる」⇔「イケメンと色気がある は違う」、「厳罰化しても犯罪はなくならない」⇔「本当に悪い人ほど罰せない」）。YouTubeのタイトルテスト機能を使っていると思われる。

## 3. 台本の構造（字幕から分析：「ミステリアスな人」回、21分52秒）

- 本文は約8,300字。**ナレーション速度は約380字/分**で、全編ほぼ一定。
- 章立てはプロローグ＋5章＋エピローグ。各章 2〜4.5分。章タイトルは文学的（「アキレスは亀を抱けない」など）で、概要欄にタイムスタンプ。
- BGMが全編に流れ続ける（効果音ラボ、DOVA-SYNDROMEのフリー素材）。

| パート | 長さ | 役割 |
|---|---|---|
| プロローグ（約1分40秒） | 誰もが感じている現象を提示 → 「だが説明できない」という矛盾 → 問いを畳みかける → 「〇〇・△△・□□の3つの視点から解剖する」と宣言 |
| 1章 | 意外な角度から入る（この回は政治記事の「色気」という用法と語源）。年号や文学作品で知的な導入 |
| 2〜3章 | 調査データ・論文を投入（調査人数や年号を多用）。問いの数が多い＝視聴者を引っ張る区間 |
| 4〜5章 | 通説（安い恋愛テク等）を一度持ち上げてから否定し、学術的な説明で上書き。問いは減り、断定が増える |
| エピローグ（約2分） | 一段抽象化した人生訓で締める → 定型句「そんなことを考えすぎてみました」→ 登録・高評価のお願い |

文体：「我々」（1本で22回）、「〜なのだろうか」「〜なのである」の評論調。主語を視聴者と一体化させる。

## 4. 信頼性の担保

- 概要欄に**参考文献を番号付きで10〜20件**（論文は著者・年・誌名・巻号まで）。
- 各文献に「何を測った研究か／どこまで言えるか」の注記を付ける。
- 「研究結果を〇〇の解釈に結びつけた部分は本動画の考察です」と、事実と考察を明確に分ける。
- チャンネル概要に「誤りはコメントで指摘を。概要欄か固定コメントで訂正」と明記。

## 5. 運営の推測

1本あたり約8,000字の台本＋20本前後の文献を2〜3日に1本出すペースは、個人の手作業では難しい。
- 文献探索・要約・台本ドラフトに生成AIを使い、人間は「問いの設計」「論理構成」「ファクトチェック」に集中している可能性が高い。
- 映像・BGM・章構成・定型句がフォーマット化されていて、制作をパイプライン化している。
- 初期の毎日投稿で母数を作り、伸びた後は品質重視で頻度を落としている。

## 6. 釣りデータ管理プロジェクトへの応用案

**型をそのまま移植できる**：「なぜ『釣り人の身近な疑問』は〜なのか【生態学×〇〇】」

ネタ例：
- なぜ荒川のハゼは秋に「急にデカくなる」のか【魚類生態学×水温データ】
- なぜシーバスは「雨の後」に釣れるのか【行動生態学×気象統計】
- なぜ東京湾の釣果は「潮見表」通りにいかないのか【海洋物理学】
- なぜ「釣れる釣り場」には人が集まりすぎて釣れなくなるのか【ゲーム理論×漁業資源学】

パイプラインに落とすなら：
1. **問いの在庫**：釣り人の疑問を集めてストックする（YouTube釣り動画のコメント、釣果データの異常値、季節の変化）
2. **データ層**：既存の釣果・釣り場・魚種・季節データ＋水温/潮/気象などの公開データ
3. **文献層**：論文・水産試験場報告をAIで検索・要約し、出典リストを自動生成
4. **台本生成**：上記3章の構造テンプレ（現象提示→矛盾→意外な導入→データ→通説否定→一段上の結論→定型句）でドラフト
5. **人の介入ポイント**：問いの選定と最終ファクトチェックのみ
6. **出力**：長尺台本（約380字/分換算で尺を逆算）、X/Threads用の短文、概要欄（章タイムスタンプ＋番号付き出典＋事実/考察の区別）
7. **タイトルは複数案生成**してA/Bテスト前提にする
